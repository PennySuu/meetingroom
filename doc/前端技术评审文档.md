## 1. 文档目的

本文档从前端视角对**信息架构与交互还原**、**技术栈与 UI 选型**、**认证与会话**、**API 对接与错误体验**、**状态与路由**、**无障碍与隐私展示**、**测试与性能**进行评审锚点说明，便于实现与变更审计。实现细节以 **`openspec/specs/openapi.yaml`** 为准；冲突时以 **`openapi.yaml`** 更新为准。

## 3. UI 组件库与视觉策略

### 3.1 硬性约束

| 约束 | 说明 |
|------|------|
| **禁止使用 Element UI / Element Plus** | 不引入 `@element-plus/*` 及同类 Element 体系依赖；设计评审与代码审查需显式检查。 |

### 3.2 已定方案：无样式（Headless）+ Design Token

本期 **不采用** 成套视觉组件库（在 §3.1 Element 禁令之外，亦**不依赖** Naive / Arco / PrimeVue 等重型 UI 套件），统一采用：

| 层级 | 选型 | 说明 |
|------|------|------|
| 交互与可达性 | **Radix Vue**（优先）或 **Headless UI（Vue）** | 无默认皮肤，提供 WAI-ARIA、焦点与键盘行为；对话框/下拉/Checkbox Group 等与 Vue 3 契合 |
| 样式与 Design Token | **Tailwind CSS** + **CSS 变量（`:root`）** | Tailwind `theme.extend` 映射 **语义化 Token**（颜色、间距、圆角、字体、阴影）；必要时局部 CSS Variables 供运行时主题预留 |
| 浮动层 | **Floating UI**（`@floating-ui/vue`） | Popover、下拉、Tooltip 对齐与翻转 |
| 自研展示层 | `src/components/base/*`（`BaseButton`、`BaseInput`、`BaseModal` 等） | 仅在 Headless 之上封装 **本项目** 的边框、间距与动效；**禁止**拷贝带默认主题的第三方 UI 皮肤 |

**MVP 落地**：表单、分页、日历栅格、侧栏、Toast 等均基于 **Token + 自研壳组件**；日历/时间轴为业务核心，**自定义布局**优先于通用 DatePicker 插件。

**工期与复杂度控制（评审补充）**：全自研日历（栅格、键盘、无障碍、多端）易导致 MVP 范围膨胀。**建议分两阶段**：**P1** 固定工作日 **`08:00–20:00`**、**30 分钟或 1 小时粒度**槽位 + 区间选择与校验（满足 ≤4h、不跨日、不可约过去）；**P2** 再细化拖拽、更小粒度或非连续槽位。**契约层**（`GET .../calendar` 的 **`date`/`timeZone`**、占用 **`startAt`/`endAt`**）不因 P1 简化而改变，仅前端展示粒度取舍。

### 3.3 Design Token 落地与交互还原

| Token 管理 | 建议 |
|------------|------|
| 源文件 | `src/styles/tokens.css`（或 `design-tokens` 单文件）定义 `--color-*`、`--space-*`、`--radius-*` 等；Tailwind `theme.extend` 引用同一套，避免双处手改 |
| 语义化 | 使用 `primary`、`surface`、`danger`、`occupied`、`free` 等 **语义名**，占/闲、主按钮等统一从 Token 取色 |
| 暗色（可选） | `[data-theme="dark"]` 下覆写 CSS 变量，**不**在业务组件里写死十六进制 |

| 产品要求（摘自产品文档） | 前端落点 |
|--------------------------|----------|
| 页头：产品名、登录态区分 | `TheAppHeader.vue`；未登录「登录/注册」，已登录用户菜单（我的预约、退出） |
| 列表筛选：容量、设施多选 | 受控筛选状态同步 URL Query（可选）或 Pinia；**空选 = 不限** |
| 日历：占用/空闲视觉区分 | 色板与图例；**已占用格文案固定为「已占用」**，不接他人 `title` |
| 新建预约：侧栏/弹窗 | `Teleport` + 焦点陷阱；**开始 & 结束**、主题、≤4h 提示 |
| 二次确认取消 | Modal + 明确后果文案；按钮 loading 防重复 |
| 加载失败 + 重试 | 区块级 `ErrorState` 组件 |

## 4. 信息架构与路由设计

### 4.1 路由表（评审稿）

| 路径 | 页面 | 访客可读 | 说明 |
|------|------|----------|------|
| `/` 或 `/rooms` | 会议室列表 | 是 | 产品 §9.1 |
| `/rooms/:roomId/calendar` | 预约日历 | 是 | 提交预约需登录；深链保留 |
| `/bookings/mine` | 我的预约 | **否** | 401 → 登录回跳 |
| `/auth/login` | 登录 | 是 | 支持 `redirect` Query |
| `/auth/register` | 注册 | 是 | 成功后默认进会议室列表或 `redirect` |

### 4.2 导航守卫与「意图保留」

| 场景 | 行为 |
|------|------|
| 未登录访问 `/bookings/mine` | 跳转登录，`redirect` 为完整路径 |
| 访客在日历填单后点「确认预约」 | 跳转登录/注册前，将 `roomId`、所选 `startAt/endAt`、**草稿 title** 写入 **sessionStorage** 或短期 Pinia + 持久化，登录成功后 **恢复侧栏并定位日期**（产品 §8.4） |
| 会话过期（401 / `AUTH_TOKEN_EXPIRED`） | 全局拦截：Toast「登录已过期」；保留当前 path 用于回跳（产品 §6.5） |

## 5. 认证、安全与凭证（对齐后端评审 + `shared.security`）

### 5.1 Cookie 与 CSRF

| 项 | 要求 |
|----|------|
| Axios | `withCredentials: true`；生产与后端 **同站或 CORS 白名单** 配置一致 |
| CSRF | 若后端下发 CSRF Token：登录后写入内存或 Cookie（非 HttpOnly 可读段），**变更类请求**头携带；若依赖 **SameSite** Cookie，与后端策略一致并文档化 |
| 存储 | **禁止**将 Session Id、长期 Token 写入 `localStorage`（config） |

### 5.2 密码与注册/登录表单

| 项 | 要求 |
|----|------|
| 传输 | 仅通过 **HTTPS**；密码框 `autocomplete` 合理 |
| 预哈希 | 与 **`openspec/specs/README.md` + `openapi.yaml`** 一致：先 **`GET /v1/auth/password-params`** 取 **`pepper` / `formulaVersion`**；**formulaVersion=1** 时按约定计算 **`passwordPrehash`**（64 位小写十六进制）。**`POST /v1/auth/register`、`POST /v1/auth/login`** 请求体 **仅发送 `passwordPrehash`**，**禁止**发送明文口令字段。**禁止**将口令、`passwordPrehash` 写入日志 |
| 防枚举 | 登录失败展示**统一文案**（产品 §6.3）；与 `message` 映射表一致，不自行拆分「用户不存在」类提示 |
| 注册 | **409 / `USER_USERNAME_CONFLICT`** 时可展示「用户名已占用」（与契约、产品一致） |

### 5.3 退出登录

调用 `POST /v1/auth/logout`；成功后清理 Pinia 用户态、可选清理草稿意图；轻提示「已退出」（产品 §6.4）。

## 6. API 客户端与统一响应（对齐 `rules.api`）

### 6.1 请求拦截器

| 头 | 规则 |
|----|------|
| `X-Request-ID` | 每次请求生成 UUID；与监控/Sentry 关联（config） |
| `Content-Type` | `application/json` |
| `Idempotency-Key` | `POST /v1/bookings` **必须**；重试时使用同一 key（后端评审 §3.4） |
| `X-CSRF-Token` | Cookie 会话且后端启用 CSRF 时，**变更类请求**携带（与 **`openapi.yaml`** 一致） |

### 6.2 响应拦截器

解析 `{ success, code, message, data }`：

- `success === true`：返回 `data` 泛型结果  
- `success === false`：抛出结构化错误（含 `code`、`message`、`httpStatus`），由 UI 层映射 Toast/表单错误  

### 6.3 HTTP 状态与产品文案

| HTTP | 典型 `code` | 前端行为 |
|------|-------------|----------|
| 401 | `AUTH_*` | 清会话态、引导登录、保留回跳 |
| 403 | `PERMISSION_DENIED` | Toast |
| 404 | `RESOURCE_NOT_FOUND` | 404 页或内联错误 |
| 409 | `BOOKING_CONFLICT_ROOM` / `BOOKING_CONFLICT_USER` | **`BOOKING_CONFLICT_USER`**：读取 **`data.conflictingRoom.name`**（及 `id`）展示产品 §10 文案；**`BOOKING_CONFLICT_ROOM`**：会议室冲突提示；完成后刷新 **`GET .../calendar`** |
| 409 | `USER_USERNAME_CONFLICT` | 注册页字段级/全局提示用户名已占用 |
| 422 | `VALIDATION_FAILED` | 表单字段/全局提示；含跨日、超 4h、过去时间等 |
| 429 | `RATE_LIMIT_EXCEEDED` | 读取 **`Retry-After`**，按钮冷却或倒计时；**`POST /v1/auth/login`** 被限流时同左（与 `openapi`、后端 §9.1 一致） |
| 500 | `SYSTEM_*` | 通用友好文案，不暴露堆栈 |

### 6.4 分页与排序

与后端一致：`page` 默认 0、`size` 默认 10；我的预约 `sort=startAt,desc`（后端评审 §3.1）。

## 7. 页面级实现要点（高度还原交互）

### 7.1 会议室列表（§9.1）

- **卡片/行**：名称、位置、人数、设施标签；主按钮「去预约」→ `calendar`  
- **列表请求**：**`GET /v1/rooms`**；筛选与契约一致：**`capacityGte`**（整数）；**`amenity`** 使用 **重复 query key**（Axios **`paramsSerializer`** 或等价），例如 `amenity=projector&amenity=whiteboard`，**不使用**未经契约约定的逗号拼接形式  
- **空状态**：无数据与筛选无结果两套文案  
- **性能**：列表 `:key` 使用 `room.id`；图片若有则懒加载  

### 7.2 预约日历（§9.2）

| 能力 | 实现要点 |
|------|----------|
| 上下文条 | 展示会议室 **名称 + 位置** |
| 日历数据 | **`GET /v1/rooms/{roomId}/calendar`**；**必选 Query：`date=YYYY-MM-DD`**（当前选中业务日）；**可选 `timeZone`**（默认与 **`conventions.md`** 一致，前后端商定即可）。响应 **`data.items[]`** 仅用 **`startAt`/`endAt`** 绘制占用块；**字段级忽略**他人 `title`、`userId`（若后端误返需兜底剔除） |
| 日期 | Date 选择器禁止过去日期；默认**今天** |
| 时间格 | 当日栅格；**已占用**仅展示「已占用」，**不渲染**他人 `title` |
| 交互 | 过去格：点击 Toast「不能预约过去的时间」；**结束 > 开始**；跨度 >4h 即时禁用提交并提示 |
| 跨日 | 客户端拦截跨自然日提交；与后端 `VALIDATION_FAILED` 双保险（产品 §11.2） |
| 并发失败 | 提交后 409 → 刷新 `GET .../calendar` |
| 幂等 | 同一确认操作复用 `Idempotency-Key` 直至成功或明确失败 |

**时间类型**：展示层使用用户时区；与后端交互 **ISO-8601** 字符串；**业务判定**以服务端为准，前端不「硬编当前时刻」做唯一可信源（后端评审 §6.1），可拉取 `Date` header 或依赖接口错误回写。

### 7.3 我的预约（§9.3）

- 筛选：会议室、日期起止、重置  
- 列表：会议室、日期、时段、**本人主题**；排序与后端一致  
- 取消：`未开始` 可点；`进行中/已结束` **禁用或隐藏**并附说明（产品 §11.5）  
- 二次确认 + loading；成功后更新列表并可使 `invalidateQueries` 式刷新相关日历（若同页无日历，依赖下次进入）  
- 分页：上一页/下一页或页码；页大小固定或可选（产品允许固定以控本）  

### 7.4 注册 / 登录

- 字段与校验与产品 §6.2、§6.3 对齐；密码强度 UI 实时提示  
- **成功后**：优先 `redirect`，否则会议室列表  
- **记住我**：若做，仅延长会话体验，不存储密码（产品 §6.3）

## 8. 状态管理（Pinia）

| Store | 职责 |
|-------|------|
| `useAuthStore` | 登录态、当前用户摘要、`login`/`logout`/`register` action |
| `useRoomFilterStore`（可选） | 列表筛选条件跨页保留 |
| `useBookingIntentStore` | 访客提交前草稿：roomId、日期、时间段、title，登录后消费 |

**原则**：能由路由与页面局部 `ref` 解决的，不升 Store（config：Pinia 仅跨组件共享）。

## 9. 可组合逻辑（Composables）

建议抽取（`use*` 命名，附 JSDoc）：

| Composable | 职责 |
|------------|------|
| `useApiClient` | Axios 实例与拦截器挂载 |
| `useAuthGuard` | 守卫、回跳参数 |
| `useRoomList` | 列表加载、筛选、重试 |
| `useRoomCalendar` | 按日加载占用、刷新、与本地选择联动 |
| `useMyBookings` | 分页、筛选、取消流程 |
| `usePasswordHasher` | **`formulaVersion=1`**：按 **`openspec/specs/README.md`** 拼接输入并 SHA-256；产出 **`passwordPrehash`**；与 **`GET /v1/auth/password-params`** 联动缓存 |

单个 composable 与组件需满足 **函数 ≤50 行、嵌套≤3** 等复杂度约束（config）；过长则拆分。

## 10. TypeScript 类型与契约

- DTO 命名与后端一致：`RoomDTO`、`BookingDTO`、`CreateBookingRequest`、`PageResponse<T>`、`ApiResponse<T>`（config）  
- 日历占用片段类型**不包含**他人 `title` 字段；若 OpenAPI 生成类型含可选字段，前端列表渲染仍不得使用他人主题  
- 枚举与 `code` 字面量联合类型：`type ErrorCode = 'BOOKING_CONFLICT_ROOM' | ...`
